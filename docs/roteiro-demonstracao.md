# Roteiro do vídeo de demonstração (cerca de 2 minutos)

Para o portfólio, o LinkedIn ou uma conversa com comerciantes. Grave a tela com a **Ferramenta de Captura do Windows** (Win + Shift + S → modo vídeo) ou com o **OBS**.

> Use **apenas dados fictícios**. Antes de gravar, clique em "Restaurar dados de exemplo" (modo demonstração) ou use uma conta de teste.

## Preparação

- [ ] Navegador em tela cheia (F11), zoom em 100% e sem outras abas visíveis.
- [ ] Ligar *Efeitos de animação* no Windows (para as animações aparecerem).
- [ ] Notificações desligadas (modo "Não perturbe").
- [ ] Ensaiar uma vez antes de gravar.

## Roteiro

| Tempo | Na tela | O que dizer (sugestão) |
|---|---|---|
| 0:00–0:10 | Abrir o site numa aba nova: a abertura toca | "Este é o StockFlow, um sistema de controle de estoque para pequenos comércios." |
| 0:10–0:20 | Tela de login | "Dá para criar uma conta, com cada loja isolada no banco, ou explorar uma demonstração sem cadastro." |
| 0:20–0:40 | Entrar → dashboard; apontar a lista "Precisa de reposição" | "O dashboard mostra o que precisa de reposição. A barra é o estoque atual e o traço é o mínimo definido para cada produto." |
| 0:40–1:00 | Produtos → buscar "racao" (sem acento) → filtro "Só abaixo do mínimo" | "A busca ignora acentos, e dá para filtrar só o que está acabando." |
| 1:00–1:25 | "Movimentar" → Saída de 50 unidades (prévia vermelha) → trocar para 2 → registrar | "Não dá para tirar mais do que existe: o sistema bloqueia aqui e também no banco de dados." |
| 1:25–1:40 | Movimentações: histórico com autor e motivo | "Toda mudança de estoque fica registrada: quem fez, quando e por quê." |
| 1:40–1:55 | Diminuir a janela ou mostrar no celular | "Funciona no celular também." |
| 1:55–2:10 | (opcional) Slide ou print do código SQL / testes | "Por trás: PostgreSQL com Row Level Security, funções transacionais e 71 testes automatizados." |

## Para conversar com comerciantes (Etapa 8)

Mostre o vídeo ou a demonstração **depois** de perguntar como eles controlam o estoque hoje. Não prometa funcionalidades que ainda não existem (vendas, código de barras, nota fiscal). Diga que é um projeto em validação.
